# 適応度関数

## 目的

ループエンジニアリングでは、単にテストが通る変更ではなく、完成形への距離が縮む変更だけを残す。評価は`concept`、`implementation`、`release`の3段階で行い、段階を下げて合格させてはならない。

## 共通原則

- ハードゲート違反が1件でもあれば、その段階は不合格。
- 合計点は100点、合格は85点以上。
- 前回より合計が2点以上下がる変更は、理由と回復計画がなければ採用しない。
- 自動点だけを上げる冗長なノード、無意味な選択肢、ダミーファイルを禁止する。
- 数値化できない魅力はrelease段階の人手評価で必ず補う。

## 段階別の重み

| 段階 | Story | Narrative | Docs | Architecture | Release Evidence |
| --- | ---: | ---: | ---: | ---: | ---: |
| concept | 60 | 20 | 20 | 0 | 0 |
| implementation | 30 | 10 | 10 | 50 | 0 |
| release | 15 | 10 | 10 | 25 | 40 |

## Story適応度

### ハードゲート

- JSONが読み込める。
- ノードIDが一意で、開始ノードとすべての遷移先が存在する。
- 到達不能ノードと循環がない。
- すべての経路が`ending`へ到達する。
- 件名、本文、選択肢が表示長上限以内である。
- 各選択ノードは2〜3択で、選択先が重複しない。
- 各選択肢はIDを持ち、同じ選択ノード内で重複しない。
- 各経路に3回以上の選択と2種類以上の到達可能な終端がある。
- 必須ビートが指定順で全経路に現れる。

### 加点100点

| 項目 | 点 | 機械評価の内容 |
| --- | ---: | --- |
| 構造 | 25 | 到達可能性、終端、経路長、ノード整合性 |
| 表示適合 | 20 | 件名、本文、選択肢、空文字の有無 |
| ペーシング | 20 | 初回選択、添付登場、3幕、経路長 |
| エージェンシー | 20 | 選択回数、固有の直後反応、効果、複数終端 |
| 情報開示 | 15 | 必須ビート順、人物ビート、添付の存在 |

## Narrative Persona適応度

構造を通った全経路について、5つの独立sub-agent人格が同じルーブリックを使い、面白さと非凡庸性を1〜5の整数で採点する。人格ごとに物差しは変えず、注目点だけを変えることで意見差も観測する。

### 5人格

| 人格 | 主な観点 |
| --- | --- |
| 通勤中のサスペンス読者 | 導入、離脱点、次話への牽引力 |
| SF・ホラー多読の辛口批評家 | 主要反転の予測可能性、類型の変形 |
| インタラクティブ物語設計者 | 選択の迷い、合流後にも残る結果、終端差 |
| 人物ドラマ重視の読者 | ミナ固有の声、感情的な反転、死者を扱う倫理 |
| ウェアラブル懐疑派 | G2、三択、1-bit画像が物語機構として必要か |

### 採点軸

面白さは`hook`、`momentum`、`choiceTension`、`revealPayoff`、`endingPull`、非凡庸性は`premiseSpecificity`、`voiceSpecificity`、`revealFreshness`、`deviceIntegration`、`clicheResistance`で評価する。1点を0、2点を25、3点を50、4点を75、5点を100へ正規化し、各群を同じ重みで集約する。Narrative総合点は面白さと非凡庸性の50:50とする。

人格内では全経路の算術平均、人格間と各経路の合議では中央値を使う。全体とは別に最低経路を保持し、凡庸と判定した人格数、ありがちな類型に同意した人格数と該当経路数、人格間の点差も出力する。

### 証跡ハードゲート

- 必須5人格が、他人格の点数を見ず、一意なsub-agent taskNameで独立評価している。
- 全人格が現在の全27経路を評価している。
- すべての点数が1〜5の整数である。
- 各経路に、その経路内の根拠ノードIDが2件以上ある。
- 面白さと非凡庸性の理由、6種類の強制置換テスト、総評が記録されている。
- 物語、人格、ルーブリック、共通レビュープロトコル、テンプレート値、全経路トランスクリプトから作るSHA-256が一致する。
- 経路IDは選択ノードIDとchoice IDの組で一意になり、同一ノード内のchoice IDも重複しない。

構造ゲートに失敗した物語は「通ったシナリオ」ではないため、Narrative評価を省略する。台詞、遷移、人格、基準の変更でdigestが変わった場合は、既存レビューを`NARRATIVE_REVIEW_STALE`として拒否する。

### 品質ハードゲート

| 項目 | 閾値 |
| --- | ---: |
| 面白さ合議点 | 70以上 |
| 非凡庸性合議点 | 65以上 |
| 総合合議点 | 68以上 |
| 最低経路 | 60以上 |
| 非凡庸性65未満の人格 | 2人以下 |
| 同じ凡庸さ強制テストの検出 | 3人格未満 |

品質不足はimplementationまでは警告とNarrative点へ反映し、`npm run narrative:verify`およびrelease段階でハードゲートにする。人格間の総合点差30以上は、閾値の平均化ではなく要確認の警告とする。

### 凡庸さの強制テスト

各人格は感想だけでなく、選択を消しても筋が変わらないか、人物を交換できるか、スマートフォンへ置換できるか、序盤で反転を予測できるか、未変形の類型が積み重なっていないか、終端をありがちな一文へ還元できるかを明示的に判定する。`genericityDetected: true`は「作品がテストに合格」ではなく「質問に書かれた凡庸さを検出」の意味に固定する。同じテストを3人格以上が検出した場合は、点数が高くても品質ゲートを通さない。

## Architecture適応度

### implementation以降のハードゲート

- 目標モジュールが存在する。
- `src/main.ts`が120行以内である。
- `src/domain/`がDOM、`window`、Even Hub SDKを参照しない。
- `test`、`build`、`fitness`、`loop:check`スクリプトが存在する。
- MVPの`app.json`に未使用権限がない。
- 物語遷移の自動テストが存在する。

### 加点100点

| 項目 | 点 | 評価 |
| --- | ---: | --- |
| モジュール境界 | 30 | 必須ファイル、mainの薄さ、依存方向 |
| テスト容易性 | 25 | 純粋遷移、Fake Port、全経路テスト |
| SDK適合 | 20 | 画像直列化、差分更新、正規終了 |
| 復元性 | 15 | 保存、revision、再起動、失敗時復旧 |
| 最小権限 | 10 | 権限、ネットワーク、秘密情報 |

## Gameplay / Narrativeの人手適応度

release evidenceでは5段階で評価する。

これは実ユーザーと人間の反応を測る別ゲートであり、Narrative Persona適応度の代替ではない。

| 項目 | 合格条件 | 質問 |
| --- | ---: | --- |
| Hook | 4以上 | 60秒以内に異常と目的を理解できたか |
| Character Voice | 4以上 | 名前を隠してもミナの文体を識別できるか |
| Temporal Mystery | 4以上 | 続きを知りたい具体的な疑問が残ったか |
| Choice Tension | 4以上 | 少なくとも1回、返信を迷ったか |
| Ending Pull | 4以上 | 次話を自発的に読みたいか |
| Device Fit | 4以上 | スマホではなくG2である意味を感じたか |

平均4.0以上かつ、3以下の項目がないことをreleaseゲートにする。

## Release Evidence

- シミュレータ全経路の結果とスクリーンショット
- 実機全経路の結果
- 画像送信失敗と再試行
- アプリ再起動からの復元
- ロック状態と2分アイドル後の操作
- 5人以上のユーザーテスト集計
- 未解決のP0/P1不具合が0件

証拠は[`harness/evidence.json`](../harness/evidence.json)へ記録し、`release`プロファイルが検査する。

## 適応度の解釈

- **85〜89:** 合格だが弱い。最小の修正で90を狙う。
- **90〜94:** デモ可能。実機差分と物語の磨き込みへ進む。
- **95〜100:** 数値上の追加最適化を止め、人間の反応と安定性を優先する。
- **ハードゲート失敗:** 点数に関係なく直ちに修正する。
