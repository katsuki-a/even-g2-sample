# プロダクト要件

## スコープ

この文書は第1話「届いてる？」を、G2単体で始めから終わりまで体験できる完成条件を定義する。優先度は`P0`が必須、`P1`が完成度向上、`P2`が将来候補である。

## 表示・操作要件

- 件名は24文字以内、本文は160文字以内、選択肢ラベルは24文字以内とする。
- メール本文は1画面1要点を原則とし、長文をスクロールさせない。
- 画面上部に`時刻 / 電波 / 電池`、中央に本文、下部に操作ヒントを置く。
- 点滅は新着とカーソルに限定し、常時グリッチを避ける。
- 色の違いだけで状態を伝えず、記号、罫線、明度差を併用する。
- 主要操作は`上 / 下 / 決定 / 戻る`へ正規化する。ダブルタップは必須操作にしない。
- 添付画像は人物の判別に必要な輪郭と表情を優先し、細部を詰め込まない。

## 非機能要件

| ID | 要件 |
| --- | --- |
| NFR-001 | ネットワーク、マイク、位置、カメラ、アルバム権限をMVPでは要求しない |
| NFR-002 | 物語状態をJSON直列化可能な純粋データとして保持する |
| NFR-003 | 時刻、保存、G2ブリッジをPortとして差し替え可能にする |
| NFR-004 | すべてのストーリー遷移をブラウザなしでテスト可能にする |
| NFR-005 | 同一の初期状態と選択列から同一の終端へ到達する |
| NFR-006 | 画像更新を並列実行せず、失敗をユーザーへ表示して再試行可能にする |
| NFR-007 | `src/main.ts`を起動処理だけに限定し、120行以内を目標にする |
| NFR-008 | ドメイン層からDOMとEven Hub SDKを参照しない |
| NFR-009 | APIキー、個人情報、音声データを保存しない |
| NFR-010 | AndroidでWebViewが再生成されても最後の確定済みノードから再開する |

## MVPで使用する権限

`permissions`は空配列とする。電池や入力の取得に追加権限が必要になった場合だけ、実機検証後に最小限追加する。

Hardware Labで宣言しているマイク、位置、アルバム、カメラ権限は製品化ブランチでは削除する。未使用権限を「将来用」として残さない。

## 完成条件

### Concept

- 必須ドキュメントが揃っている。
- `content/story.json`が構文、参照、到達可能性、表示長、物語ビートの検査に合格する。
- concept適応度が85点以上である。

### Implementation

- 目標モジュール境界へ分割され、純粋な物語遷移テストが通る。
- `npm run loop:check:implementation`が成功する。
- 権限が最小化され、すべての経路を自動走査できる。
- シミュレータで全メール、選択、添付、復元、終了を確認する。

### Release

- 実機で全経路を完走し、画像失敗から復旧できる。
- ロック状態、再起動、2分アイドル後に復元・操作できる。
- 5人のテストで、最初の異常を60秒以内に理解した人が4人以上いる。
- 5人のうち4人以上が「続きを読みたい」を4/5以上で評価する。
- release適応度が85点以上で、重大な手動ゲートがすべて確認済みである。
